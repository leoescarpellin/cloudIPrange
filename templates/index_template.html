Firewall Quick-Start Integration

Select a firewall model above to display setup instructions and alias configuration.

pfSense (URL Table Aliases)

  1. In pfSense WebGUI, navigate to Firewall → Aliases → IP and click Add.
  2. Configure the alias:
    • Name: Azure_Storage_IPv4 or AWS_SaoPaulo_IPv4
    • Type: Select URL Table (IPs).
    • URL Examples:
      • Azure: https://leoescarpellin.github.io/cloudIPrange/ranges-services/AzureStorage.ipv4.txt
      • AWS: https://leoescarpellin.github.io/cloudIPrange/aws/ranges-regions/sa-east-1.ipv4.txt
      • GCP: https://leoescarpellin.github.io/cloudIPrange/gcp/ranges-regions/southamerica-east1.ipv4.txt
      • Cloudflare: https://leoescarpellin.github.io/cloudIPrange/cloudflare/cloudflare.ipv4.txt
    • Update Frequency: Enter 1 day (or 7 days).
  3. Click Save and Apply Changes. pfSense will fetch and load the CIDRs into packet filter (pf).
  4. In Firewall → Rules, select the alias as the Source or Destination.
Best Practice: Always use .ipv4.txt for IPv4 rules and .ipv6.txt for IPv6 rules. pfSense produces an error if IPv6 addresses are present inside an alias assigned to an IPv4 rule.
Web Filtering (SquidGuard): For URL and domain filtering in pfSense SquidGuard, use our UT1 Toulouse Blacklist Mirror (Shallalist Successor).

OPNsense (URL Table Aliases)

  1. Navigate to Firewall → Aliases and click + (Add).
  2. Configure the alias:
    • Enabled: Checked.
    • Name: Azure_BrazilSouth / AWS_SAEast
    • Type: URL Table (IPs)
    • Content: https://leoescarpellin.github.io/cloudIPrange/ranges-regions/brazilsouth.ipv4.txt (or AWS / GCP / Cloudflare URL)
    • Refresh Frequency: 1 (days).
  3. Click Save and Apply Changes. OPNsense will download and cache the table in memory.

Palo Alto Networks (External Dynamic Lists - EDL)

  1. Navigate to Objects → External Dynamic Lists and click Add.
  2. Set Name (e.g., EDL-Azure-Storage) and Type to IP List.
  3. In the Source tab:
    • Source URL: https://leoescarpellin.github.io/cloudIPrange/ranges-services/AzureStorage.txt (or .ipv4.txt).
    • Repeat: Select Daily or Weekly.
  4. Click OK, commit configuration, and add the EDL object to your Security Policy rule.

MikroTik RouterOS (Address Lists & Script)

  1. In WinBox or Terminal, create a scheduled script under System → Scripts: 
    /tool fetch url="https://leoescarpellin.github.io/cloudIPrange/ranges-regions/brazilsouth.ipv4.txt" dst-path="azure_brazil.txt"
:local content [/file get azure_brazil.txt contents]
:local lineEnd 0
:local line ""
/ip firewall address-list remove [find list="Azure_BrazilSouth"]
:while ([:len $content] > 0) do={
  :set lineEnd [:find $content "\n"]
  :if ($lineEnd = -1) do={:set lineEnd [:len $content]}
  :set line [:pick $content 0 $lineEnd]
  :set content [:pick $content ($lineEnd + 1) [:len $content]]
  :if ([:len $line] > 0) do={
    /ip firewall address-list add list="Azure_BrazilSouth" address=$line comment="Azure IP Range"
  }
}
  2. Schedule under System → Scheduler to run daily or weekly.

Fortinet FortiGate (External Threat Feeds)

  1. Go to Security Fabric → Fabric Connectors and click Create New.
  2. Select Threat Feeds → IP Address.
  3. Configure the connector:
    • Name: Azure_Storage_Feed or Cloudflare_Feed
    • URL: https://leoescarpellin.github.io/cloudIPrange/ranges-services/AzureStorage.ipv4.txt
    • Refresh Rate: Daily (or every 1440 minutes).
  4. Use the created Fabric Connector object as Source/Destination in your Firewall Policies.

Cisco Firepower (FMC) / ASA

  1. In Firepower Management Center (FMC), navigate to Objects → Object Management → Security Intelligence → Network Lists and Feeds.
  2. Click Add Network Lists and Feeds:
    • Name: Cloud_Services_Feed
    • Type: Feed
    • Feed URL: https://leoescarpellin.github.io/cloudIPrange/ranges-services/AzureStorage.ipv4.txt
    • Update Frequency: Daily
  3. Deploy changes to Firepower Threat Defense (FTD).

Engine & CIDR Optimizations

Strict CIDR Collapsing: Nested subnets are automatically eliminated (e.g. /26 inside a /16 is absorbed into the parent /16) and contiguous blocks are merged, reducing firewall table memory footprint by up to 70%.

Protocol Separation: Every service and region is published with separate .ipv4.txt and .ipv6.txt lists to prevent family mismatch errors in pfSense and OPNsense rules.

Canonical Sorting: Sorted numerically by network integer and subnet mask length.

Automated Schedule & Mirrors

Weekly Automation: Powered by GitHub Actions running every Wednesday at 11:00 UTC.

Static Mirrors: Permanent direct links to raw provider JSONs without requiring web scrapers or temporary download tokens.

Lightweight Footprint: 12-week rolling retention window with Gzip compression (<15 MB total Git footprint).
